# KQ Crew — Android Crew App

KQ Crew is a Jetpack Compose Android app so crew members can see their assigned
transit cards and delay-risk alerts, and dispatchers can view the transit list and
live crew positions.

It signs in through a cookie-based API at `http://10.0.2.2:8000/` (the Android
emulator's host-loopback address). Password sign-in sends email and password to
`POST /login`; Google sign-in sends an ID token to `POST /auth/google`. Both issue a
`kq_session` cookie. After sign-in the app checks the role, calls `GET /api/me`, and
shows `GET /api/my-transits` as one TransitCard per transit with a delay-risk label in
text and colour and an Alert marker when `open_alert` is true.

- **Crew accounts** see their own transits.
- **Dispatcher accounts** see a transit list plus live crew locations (GPS).
- **Backend:** a pytest API suite (98 checks) lives alongside this project.
- **Automatic tests:** the Android unit tests in `CrewAppLogicTest.kt` (formatTime,
  riskLabel, riskColor). The rest is verified by hand using the test sheet in
  `docs/crew_app_manual_tests.md` (MT-01 to MT-15).

## Base URL configuration

`BASE_URL` is defined in `app/src/main/java/com/donell/kqcrew/Api.kt`:

```kotlin
const val BASE_URL = "http://10.0.2.2:8000/"
```

- `10.0.2.2` is the Android emulator's host-loopback address — it always routes back
  to the computer the emulator is running on, so the API running on that machine is
  reached at `http://10.0.2.2:8000/`.
- The API must be started before the app is used. Stop it to test the "Cannot reach
  the server" message.

## Running on the Android Emulator

1. Start the API on your computer (the host):
   ```bash
   uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
   *(or however your local dev server is launched)* — it must listen on `0.0.0.0` or
   `10.0.2.2`, port 8000.

2. Open **Android Studio** and click **Tools → Device Manager** (or Shift+F1) to
   create/start a Pixel device with a system image. Start the emulator.

3. In Android Studio, **Run → Run 'app'** (or click the green ▶ with the app module
   selected). The app installs on the emulator and opens to the sign-in screen.

4. On the emulator, the API is reachable **only** at
   `http://10.0.2.2:8000/`. Use the emulator browser (Chrome/Firefox) to test the
   API directly.

> Tip: the API's CORS settings must allow the app's scheme/host, otherwise sign-in
> requests are blocked by the browser's CORS policy.

## Running on a physical device

1. Enable **Developer options** on the phone (**Settings → About phone → tap Build
   number 7 times**), then enable **USB debugging**.

2. Connect the phone to the computer with a USB cable and authorize the computer on
   the phone when prompted.

3. Confirm the device is recognised:
   ```bash
   adb devices
   ```
   You should see a device in `device` state.

4. In Android Studio, select the phone from the target device dropdown and
   **Run → Run 'app'**.

5. On the physical device, `10.0.2.2` does **not** reach the host — it is an
   emulator-only address. Instead point the app at the API using the computer's
   **LAN IP address** on the same Wi-Fi network:
   ```kotlin
   const val BASE_URL = "http://192.168.x.x:8000/"
   ```
   Replace `192.168.x.x` with the host machine's IP (find it with
   `ipconfig` on Windows or `ip addr`/`ifconfig` on macOS/Linux). Rebuild the app
   after changing the base URL.

6. On the same Wi-Fi, make sure the API listens on the machine's Wi-Fi IP:
   ```bash
   uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
   The app must be able to reach the API over the network, and the API's CORS must
   allow the device's IP/host.

> To bypass the host/device network rule temporarily, add
> `android:usesCleartextTraffic="true"` (already set in
> `AndroidManifest.xml`) so the app may load cleartext (HTTP) URLs.

## Building

```bash
./gradlew assembleDebug        # debug APK (app/build/outputs/apk/debug/app-debug.apk)
./gradlew assembleRelease      # release APK (signing config needed)
./gradlew test                 # local JVM unit tests
./gradlew connectedCheck       # UI tests on a connected device/emulator
```

`local.properties` (auto-generated by Android Studio) must not be committed — it holds
the local SDK path. `gradle.properties` enables the Gradle configuration cache; if you
have a problem, try removing the line `org.gradle.configuration-cache=true`.

## Signing the release build

Release builds require a signing configuration. The debug build uses the debug keystore
(which ships with the Android SDK and is intentionally not committed). For release, add
a `keystore` file (`.jks`/`.keystore`) to your local machine and reference it in
`app/build.gradle.kts` (or provide a `local.properties` `release.storeFile` path) — never
commit the keystore or its password. Standard Android keystore files
(`*.jks`, `*.keystore`) are git-ignored by this project.
